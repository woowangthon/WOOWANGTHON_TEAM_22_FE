# WOOWANGTHON_TEAM_22_FE

## 오늘, 그리고

AI와 대화하며 하루를 돌아보고, 직접 그린 그림으로 그림일기를 완성하는 웹 서비스입니다.
방 안의 책장과 달력을 눌러 일기를 쓰고 다시 볼 수 있습니다.

빌드 과정 없이 `index.html` 한 파일로 동작합니다. 로그인은 Supabase Auth, 대화·일기·그림 저장은 BE API(`WOOWANGTHON_TEAM_22_BE`)를 사용합니다.

## 사용 흐름

1. 오른쪽 위에서 회원가입·로그인을 한다.
2. 방 화면에서 책장("오늘의 일기 쓰기")을 누른다.
3. 책이 펼쳐지면 AI가 먼저 질문하고, 오늘 있었던 일을 이야기한다.
4. "대화 끝내기"를 두 번 눌러 대화를 마친다. 이때 AI 일기 초안을 미리 요청한다.
5. 스케치북에서 그림을 그리고 날씨를 고른 뒤 "그림일기 완성"을 누른다.
6. 그림일기 양식에 초안 글·그림·날씨가 보이면 "이대로 저장"을 누른다. 다시 그리고 싶으면 "그림 고치기"를 누른다.
7. 일기가 저장되고 그림이 올라가면 달력이 열리고 오늘의 그림일기가 펼쳐진다.
8. 나중에 달력("일기 확인")에서 날짜를 눌러 그림일기와 원본 대화를 다시 본다.

## 기능

### 방 (메인 화면)
- 창문, 소파, 화분, 액자, 책장, 벽시계, 달력으로 꾸민 방 일러스트
- 화면 크기에 맞춰 확대/축소되는 고정 레이아웃 (스크롤 없음)
  - PC 1440×900, 모바일(세로) 600×1000 기준
- 책장 옆 안내 문구: "오늘의 일기 쓰기" → 저장 전이면 "오늘의 일기 마저 쓰기" → 저장 후 "오늘의 일기 보기"
- 실제 현재 시간으로 움직이는 벽시계
- 벽 달력은 서울 기준 이번 달을 보여 주고, 일기가 있는 날에 책 아이콘 표시

### 로그인 / 회원가입 (Supabase Auth)
- 이메일·비밀번호 로그인, 이름·이메일·비밀번호 회원가입 (이름은 그림일기의 "이름" 칸에 쓰임)
- 이메일 인증을 켠 프로젝트면 가입 후 "이메일 인증 후 로그인" 안내
- 로그인 상태는 새로고침해도 유지되고, 오른쪽 위에 이름과 로그아웃 버튼 표시
- 로그인하지 않고 책장을 누르면 로그인 창이 열림

### 책장 → AI와 대화
- 책을 펼치면 BE 채팅 세션을 시작하고 AI의 첫 질문을 보여 줌
- Enter로 전송, Shift+Enter로 줄바꿈, 한글 조합 중 전송 방지 (최대 2,000자)
- AI가 답변하는 동안 입력 중 표시, 그동안은 보내기 막힘
- 전송이 실패하면 메시지에 "다시 보내기"(같은 요청 ID로 재전송) / "지우기"(입력칸으로 되돌림) 표시
- "대화 끝내기" 버튼은 두 번 눌러야 종료 (3초 안에 다시 누르지 않으면 취소)
- 일기는 서울 기준 하루에 한 권. 오늘 일기를 이미 저장했으면 책장은 그 일기를 펼침

### 스케치북 (그림 그리기)
- 이중 스프링 철이 달린 스케치북 모양의 창
- 색 16가지, 굵기 1~60, 브러시 7종 (브러시, 서예 브러시, 에어브러시, 크레용, 마커, 연필, 수채화 브러시)
- 지우개, 되돌리기, 모두 지우기 / 날씨 선택: 맑음, 흐림, 눈, 비
- 마우스와 터치 모두 지원
- "그림 고치기"로 돌아와도 그리던 그림과 날씨가 그대로 남아 있음

### 저장 전 확인 → 저장
- 그림일기 양식에 AI 초안 글, 그린 그림, 고른 날씨를 미리 보여 줌
- 초안이 아직 오지 않았으면 "초안 기다리는 중", 실패하면 "초안 다시 요청"
- "이대로 저장" → 일기 확정 저장 → 받은 `diary_id`로 그림 업로드 → 둘 다 성공해야 완료
- 그림 업로드가 실패하면 완료로 처리하지 않고 "그림 저장 다시 시도"(같은 일기, 같은 그림) 표시. 책을 닫아도 책장에서 다시 시도할 수 있음

### 달력 → 그림일기 보기
- 벽의 달력을 누르면 화면 가운데로 확대되고, ‹ › 버튼으로 다른 달을 볼 수 있음
- 날짜를 누르면 BE에서 그 날의 일기를 불러와 펼침
- **1쪽: 그림일기장 양식** — 년/월/일/요일, 날씨, 이름, 그린 그림, 일기 글
- **2쪽: 4컷 만화** — 아직 BE에서 만화가 오지 않아 빈 자리만 표시
- PC는 두 쪽을 한 번에, 모바일은 한 쪽씩 넘겨 봄 (버튼, 책 클릭, ←/→ 키)
- "대화 기록 보기": 그 일기를 쓸 때 AI와 나눈 원본 대화 (BE `messages`, `position` 순서)
- 그림 주소(300초 유효)가 만료되면 일기 상세를 다시 받아 새 주소로 바꿈

### 공통
- 키보드 조작: Enter/Space로 열기, Esc로 열린 창을 순서대로 닫기
- 오류 문구는 짧게 표시 (`인증 실패`, `저장 실패`, `요청 처리 중`, `세션 없음` 등)
- `prefers-reduced-motion` 설정 시 애니메이션 제거

## 실행 방법

```
git clone https://github.com/woowangthon/WOOWANGTHON_TEAM_22_FE.git
cd WOOWANGTHON_TEAM_22_FE
cp config.example.js config.js   # 값을 채움
```

1. `config.js`에 환경별 값을 넣습니다. (git에 올라가지 않음)
   - `API_BASE`: BE 주소 (로컬 기본값 `http://127.0.0.1:8000`)
   - `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`: Supabase 프로젝트 주소와 Publishable key (`sb_publishable_…`)
   - Supabase Secret key나 AI 공급자 키는 FE에 넣지 않습니다.
2. 로컬 서버로 엽니다. BE의 `ALLOWED_ORIGINS` 기본값이 `http://127.0.0.1:5500`, `http://localhost:5500`이므로
   VS Code Live Server(포트 5500) 등으로 그 주소에서 엽니다. `file://`로 열면 BE 요청이 CORS로 막힙니다.
3. BE와 AI 서버(Mock 모드)를 BE README대로 실행합니다.

## BE 연동

| 기능 | API | FE에서 쓰는 곳 |
|---|---|---|
| 채팅 시작 | `POST /api/chat-sessions` (`Idempotency-Key`) | 책장을 눌러 대화 책을 펼칠 때 |
| 대화 메시지 | `POST /api/chat-sessions/{session_id}/messages` (`client_message_id`) | 보내기 |
| 일기 초안 | `POST /api/chat-sessions/{session_id}/diary-draft` (`client_request_id`, `history_revision`) | 대화 끝내기 직후 |
| 일기 확정 저장 | `POST /api/chat-sessions/{session_id}/diaries` (`client_request_id`, `history_revision`, `draft_id`, `weather`) | "이대로 저장" |
| 그림 원본 업로드 | `POST /api/diaries/{diary_id}/drawing` (multipart `file`, PNG) | 확정 저장 성공 직후 |
| 월별 달력 | `GET /api/diaries?month=YYYY-MM` | 로그인 직후, 달력 열기·달 이동 |
| 일기 상세 | `GET /api/diaries/{diary_id}` | 날짜 누르기 |

- 모든 요청에 `Authorization: Bearer <Supabase access token>`. 401이면 토큰을 한 번 갱신해 같은 요청을 다시 보내고, 그래도 실패하면 로그인 창을 엶
- 요청 ID는 한 번 만들어 재시도에도 그대로 씀. 결과를 알 수 없는 실패(연결 끊김·시간 초과)나 재시도 가능 오류만 같은 ID로 다시 보냄
- `session_id`, `history_revision`, `draft_id`는 BE 응답값만 사용. 늦게 도착한 이전 응답은 화면에 반영하지 않음
- 확정 저장 본문은 처음 만든 것을 그대로 재사용. 그림 업로드 실패 시 같은 `diary_id`·같은 Blob으로만 재시도
- 저장된 데이터는 BE에서 읽음. 브라우저 `localStorage`에는 로그인 세션(Supabase)만 남음
